# Verify a generate → edit workflow

This walkthrough separates two checks: a reproducible local API integration and
a run against the image provider you choose. The bundled local example returns
one-pixel PNG fixtures; it does not demonstrate AI image quality.

## Run the local integration

From a checkout, with Node.js 20 or newer:

```bash
npm ci
node examples/verify-workflow.mjs
```

The script starts a local HTTP server on an available port, then:

1. Sends a JSON generation request through `ImageGenClient`.
2. Decodes the returned PNG into `generated-fixture.png`.
3. Uploads that file as a multipart edit request.
4. Saves and verifies `edited-fixture.png`.
5. Rejects `n=0` before another request reaches the server.
6. Writes `verification.json` beside the output files.

Each run uses a new directory under `output/imagegen-demo/`. No account, API
credit, global skill installation, or changes to personal settings are needed.
The server closes when the script finishes.

Example result:

```json
{
  "status": "ok",
  "verification": "local API and output-file integration only",
  "images": "one-pixel fixtures; not generated by an AI model",
  "operations": [
    { "operation": "generate", "path": "/v1/images/generations" },
    { "operation": "edit", "path": "/v1/images/edits" }
  ],
  "rejected_zero_before_network": true
}
```

The actual output also includes absolute paths to the files and verification
manifest. Those paths are specific to your machine.

## Run the same task against your provider

Install the CLI, then set `IMAGEGEN_API_KEY`, `IMAGEGEN_BASE_URL`, and
`IMAGEGEN_MODEL` using the values documented by your provider. A model name from
one service may not exist at another service.

```bash
npm install --global universal-imagegen-agent@0.1.2
imagegen-agent config --json
```

First inspect the request without sending it:

```bash
imagegen-agent generate "A ceramic mug on a neutral background" --model "$IMAGEGEN_MODEL" --out output/case/mug.png --dry-run --json
```

The example above uses POSIX environment-variable syntax. In PowerShell, use
`--model $env:IMAGEGEN_MODEL`; the model is also read automatically from the
environment, so the `--model` option can be omitted.

After checking the provider, model, and output path, execute:

```bash
imagegen-agent generate "A ceramic mug on a neutral background" --out output/case/mug.png --json
imagegen-agent edit --image output/case/mug.png --prompt "Change only the background to warm cream" --constraints "Keep the mug, framing, handle, and edges unchanged" --out output/case/mug-edited.png --json
```

These two commands call your configured provider and may incur its API charges.
An existing output file is preserved unless `--force` is supplied.

## What to record

For a useful compatibility report, record the package version, OS/runtime,
provider and model names, sanitized command, resulting exit code, and whether
generation and editing both worked. Include before/after images only if they
are appropriate to share. Exclude API keys, authorization headers, private
service URLs, and personal file paths.

Use the repository's **Provider compatibility feedback** issue form for results.
Successful tests are useful too: they establish which combinations have actually
been exercised.
